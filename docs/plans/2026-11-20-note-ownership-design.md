# Note ownership design

Date: 2026-11-20. Status: pending user approval.

## Intent
Авторизация в приложении есть, но заметки общие: любой вошедший видит, открывает, редактирует и удаляет все записи. Нужно, чтобы пользователь работал только со своими заметками — в списке, по прямым URL просмотра/редактирования и при удалении.

## Goals, non-goals, anti-goals
- Goal: список запрашивает и показывает только заметки текущего пользователя; новые заметки получают его `authorId`.
- Goal: прямая ссылка на чужую заметку (просмотр или редактирование) показывает явное сообщение о доступе, а не данные заметки.
- Goal: попытка удалить чужую заметку не отправляет `DELETE` и показывает то же сообщение.
- Non-goals: серверная авторизация в json-server (реальный контроль доступа), смена владельца, общие/публичные заметки, новые зависимости.
- Anti-goal: сломать tasks 1–15, дублирующий маршрут `/notes`, ErrorBoundary, 404-страницу или запрещённые файлы.

## Constraints
- Ответы в русском; UI-тексты новых сообщений английские.
- Tailwind только; без CSS-модулей, inline-стилей и новых зависимостей (`package.json` не меняется).
- Не менять `src/components/CreateNoteForm.tsx`, `src/components/NoteFilterForm.tsx`, `onTagsChange(tags: string[])`, `selectedTags.every(...)` и дублирующий маршрут `/notes` в `src/App.tsx`.
- Не коммитить `db.json`; push только по отдельной просьбе.
- Тесты остаются во внешнем CDP-харнесе `D:\opencode\tmp\opencode\tag-dropdown-test.mjs`; тестового кода в production нет.
- Контроль только на клиенте: прямой `fetch`/`curl` к json-server обходит проверку владельца. Это ограничение фиксируется явно, а не маскируется.

## Approach
Пользователь выбрал A в rationale: полный клиентский контроль всех операций плюс исправление логина и фикстур. Пользователь выбрал B для чужой заметки: явное сообщение доступа вместо «Note not found.» или тихого редиректа. Отклонены: серверная проверка (меняет dev-окружение), только фильтрация списка (чужие URL остаются доступными), сокрытие факта существования заметки.

Источник данных уже есть: `db.json` содержит `authorId` у всех заметок, а `useAuthContext()` отдаёт текущего пользователя. Новый бэкенд не нужен.

## Design
### Модель и маппинг
- `src/types.ts`: добавить `authorId?: string` в `Note` и `NoteDTO`. Поле **опциональное**: `CreateNoteForm.tsx:86-93` (файл запрещено менять) конструирует `Note` без `authorId`, и обязательное поле сломало бы `tsc`. Обязательным его сделать нельзя без правки запрещённого файла.
- `src/utils.ts`: экспортировать общую константу `OWN_NOTES_ONLY_MESSAGE = "You can only work with your own notes."` и копировать `authorId` в `mapNoteFromDTO`.

### Список (`src/pages/notesPage.tsx`)
- В `refetchNotes` добавить в `URLSearchParams` параметр `authorId` со значением `user.id`, когда пользователь есть. Запрос становится `GET /notes?authorId=<id>`; сортировка `-createdAt` и фильтры `NoteFilterForm` сохраняются.
- Если `user` отсутствует (это возможно на дублирующем `/notes` вне `Layout`), запрос не выполняется, а существующий `<Navigate to="/login" />` продолжает работать. В `useEffect` добавить `user?.id` в зависимости; комментарий `eslint-disable` оставить как есть.
- Фильтрация по тегам (`selectedTags.every(...)`) и `onTagsChange` не трогаются.
- `handleDelete(id)`: найти заметку в `notes` по `id`; если `note.authorId !== user.id`, установить `OWN_NOTES_ONLY_MESSAGE` и вернуться без `fetch`. Для своей заметки `DELETE` и обновление списка работают как сейчас.
- Сообщение выводится в уже существующем красном `<p>` для `error` — нового стиля не нужно.

### Создание (`src/pages/CreateNotePage.tsx`)
- Подключить `useAuthContext()`. В `handleSubmit` отправлять `body: JSON.stringify({ ...note, authorId: user.id })` — `CreateNoteForm` остаётся неизменным, владелец добавляется на уровне страницы.
- Если `user` отсутствует, не отправлять POST, показать `OWN_NOTES_ONLY_MESSAGE` и вернуть `false` (защита на случай рендера вне `Layout`).

### Просмотр (`src/pages/NoteViewPage.tsx`)
- Подключить `useAuthContext()`. После успешного `GET /notes/:id` сравнить `loaded.authorId` с `user.id`. При несовпадении установить `error = OWN_NOTES_ONLY_MESSAGE`, `note` не установить — заголовок остаётся «View note», тело заметки и кнопки `Edit`/`Back to notes` не показываются.
- Сообщение «Note not found.» и «Could not load note...» сохраняются для своих/несуществующих заметок и ошибок сервера.

### Редактирование (`src/pages/EditNotePage.tsx`)
- Подключить `useAuthContext()`. После загрузки заметки сравнить `authorId` с `user.id`. При несовпадении установить `error = OWN_NOTES_ONLY_MESSAGE`, не вызывать `reset()` и не ставить `loaded = true` — форма не рендерится, `PATCH` не отправляется.
- Для своей заметки поведение формы и все сообщения об ошибках остаются прежними.

### Логин (`src/pages/LoginPage.tsx`)
- Сейчас `setUser(users)` кладёт в контекст и `localStorage.user` **массив**, поэтому `user.id` равен `undefined`. Заменить на выбор одного пользователя: `users.find((u) => u.password === data.password && typeof u.id === "string" && u.id)`, затем `setUser({ id, email, password })` найденного. При нескольких совпадениях берётся первый.
- Существующие русские сообщения об ошибках логина не трогаются (вне scopes владельца).

### Локальные данные и харнес
- `db.json`: в рабочей копии заменить `authorId: "1x"` на `"1"` у всех 7 заметок, чтобы при разработке был виден начальный набор. Файл **не коммитится**.
- Фикстуры харнеса: добавить `authorId: "1"` ко всем базовым заметкам и к task-specific (`edit-note-1`, `view-note-1`, `crash-note-1`), чтобы задачи 1–15 остались зелёными.
- Fetch-shim харнеса: для `GET /notes` без `id` учитывать query-параметр `authorId`, сравнивая его с `authorId` фикстуры. Для задачи 20 параметр намеренно игнорируется — это симулирует бэкенд, который не применил фильтр, чтобы проверить защиту удаления.
- Добавить `DELETE`-ветку в shim (логирование и удаление из фикстуры), чтобы можно было доказать отсутствие запроса.
- Обновить утверждение task 9: было «login stores an array» (`Array.isArray(...) === true`), стало проверка, что `localStorage.user` — объект `{ id: "3", email: "numeric@example.com", password: "1111" }`. Старое утверждение фиксировало баг и мешает исправлению логина.

## Specification
### Inputs
| Input | Type | Required | Constraints | Default |
|---|---|---|---|---|
| `user.id` из `localStorage.user` | string | да для операций с заметками | берётся из `AuthContext` | `null` → редирект на `/login` |
| `authorId` заметки | string \| undefined | нет | отсутствует у заметок без владельца | считается чужой |
| `GET /notes?authorId=<id>` | HTTP | да для списка | фильтр json-server | — |

### Outputs
| Case | Result | Shape |
|---|---|---|
| Своя заметка в списке | карточка как сейчас | `NoteCard` с View/Edit/Delete |
| Чужая заметка в списке | не запрошена/не показана | GET с `authorId`, карточки нет |
| Создание | POST с владельцем | `__postBody.authorId === user.id` |
| Чужой `/notes/:id` | сообщение доступа | `You can only work with your own notes.` вместо тела |
| Чужой `/notes/:id/edit` | сообщение доступа | форма не рендерится, PATCH нет |
| Попытка удалить чужую | сообщение доступа | DELETE нет, карточка остаётся |

### Edge cases
| Case | Expected behaviour |
|---|---|
| Гость на дублирующем `/notes` | без запроса к `/notes`, редирект на `/login` |
| Заметка без `authorId` | считается чужой для всех пользователей |
| Два пользователя с одинаковым email/паролем | логин берёт первого найденного |
| Чужая заметка по прямому URL | доступен только общий текст доступа; заголовок не раскрывает название |
| Ошибка сети при загрузке | прежние сообщения «Could not load note...» / «Could not load notes...» |

### Acceptance criteria
- [ ] `GET /notes?...` содержит `authorId` текущего пользователя; чужие записи не приходят в списке.
- [ ] Новая заметка сохраняется с `authorId` вошедшего пользователя.
- [ ] Просмотр и редактирование чужой заметки показывают «You can only work with your own notes.».
- [ ] Попытка удалить чужую заметку не отправляет `DELETE` и показывает тот же текст.
- [ ] После реального логина `localStorage.user` — один объект с корректным `id`.
- [ ] Tasks 1–15 зелёные; tasks 16–20 зелёные; `npm run build` и `npm run lint` exit 0.
- [ ] `db.json` не закоммичен; запрещённые файлы и дублирующий `/notes` не изменены.

### Out of scope
- Серверная авторизация json-server, смена владельца, публичные заметки, тесты внутри репозитория.

## Decisions
- Пользователь (Q1): A — все операции: список, создание, просмотр, редактирование, удаление, исправление логина и фикстур.
- Пользователь (Q2): B — явное сообщение о доступе.
- Пользователь (Q3): B — локально переназначить сид-заметки на пользователя `"1"`, без коммита `db.json`.
- Пользователь (Q4): A — текст «You can only work with your own notes.» единый для просмотра, редактирования и удаления.
- Пользователь (Q5): A — при удалении чужой не отправлять DELETE и показывать тот же текст.
- Пользователь (Q6): A — обновить фикстуры и добавить задачи 16–20 во внешнем харнесе.
- Agent's call: `authorId` опциональный в типах из-за запрещённого `CreateNoteForm.tsx`.
- Agent's call: список фильтруется запросом `?authorId`, без дополнительного client-side фильтра; задачи 16–20 проверяют и запрос, и поведение при «непослушном» бэкенде.
- Agent's call: обновление утверждения task 9 (оно фиксировало баг логина).
